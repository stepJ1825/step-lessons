### Паттерн Composite (Компоновщик)
#### Задача: "Модель файловой системы"
#### Проблема: Вам необходимо разработать программу, которая рассчитывает общий размер содержимого папки. Папка может 
содержать как отдельные файлы, так и другие вложенные папки. Глубина вложенности может быть произвольной. Нежелательно писать сложный рекурсивный код, который постоянно проверяет тип элемента (файл это или папка), чтобы вызвать правильный метод для получения размера.
#### Требования:
1. Создать общий интерфейс FileSystemComponent, который объявляет метод getSize(), возвращающий размер компонента в 
байтах.
2. Создать класс File (лист), реализующий интерфейс FileSystemComponent. Файл имеет имя и размер.
3. Создать класс Directory (композит), реализующий интерфейс FileSystemComponent. Папка имеет имя и содержит коллекцию 
дочерних компонентов (FileSystemComponent).
4. Класс Directory должен предоставлять методы для добавления (addComponent), удаления (removeComponent) и получения 
дочерних компонентов.
5. Ключевой момент: Реализация метода getSize() в классе Directory должна вычислять свой размер как сумму размеров 
всех своих дочерних компонентов (и так рекурсивно для всех вложенных папок).
6. Продемонстрировать в main создание сложной древовидной структуры папок и файлов, а затем рассчитать общий размер 
для корневой папки, вызвав всего один метод — getSize().
------------------------------------------------------
### Паттерн Composite: "Иерархическая структура документа"
#### Проблема: Необходимо смоделировать текстовый документ для подсчета общего количества символов (включая пробелы и 
знаки препинания). Документ имеет сложную иерархическую структуру: он состоит из Глав, которые содержат Абзацы, которые состоят из Предложений, которые, в свою очередь, состоят из Строк, которые содержат Символы. Нужно иметь возможность легко добавлять новые уровни иерархии (например, "Разделы" между Документом и Главами) и рассчитывать общие метрики (количество символов, слов, предложений) для любого уровня вложенности, используя единый интерфейс.
#### Требования:
1. Реализовать иерархию: Документ -> Главы -> Абзацы -> Предложения -> Строки -> Символы.
2. Для каждого элемента реализовать метод getCharCount().
3. Продемонстрировать работу, создав документ со сложной структурой и посчитав общее количество символов в нем и в 
его отдельных главах.

### Паттерн Command или Strategy
#### Задача:
Переписать задание поиска слов в "Война и мир" (с выбором реализации через обычный поиск либо через регулярные 
выражения) при помощи паттерна Команда.

Команда — это поведенческий паттерн проектирования, который превращает запросы в объекты...

То есть, запрос, каким способом подсчитывать слова должен быть упакован в объект.
